> 这一档没有像素可量，证据纪律是它唯一的防线。
>
> 目录：C.0 证据标签制度 · C.1 先问清楚 · C.2 真机调研 · C.3 包内取证 · C.4 产出

## C. 功能调研（需求 / 功能 / 技术）

A、B 两档拆的是**一屏长什么样**；C 档拆的是**一个功能怎么运转**。难点完全不同：
视觉有像素可量，功能行为和技术实现**没有证据就全是猜**，而猜出来的东西看起来和实测一模一样。
所以这一档的核心不是流程，是**证据纪律**。

### C.0 ⛔ 每条结论必须挂证据标签，⛔ 无标签的句子不许进报告

| 标签 | 含义 | 必须附上 |
|---|---|---|
| `[真机]` | 你在设备上**亲眼看到它发生** | 截图 / 录屏的时间点 |
| `[包内]` | 从安装包里**追溯到具体文件** | 文件名（`libapp.so` / `classes2.dex` / 某个 asset 路径） |
| `[推断]` | **证据不足以支撑这句话** —— 包括「两者都没有」，也包括**有证据但推不到这个结论** | **为什么这么推**，一句话 |

⭐ **最容易出错的不是「没证据」，是「证据错位」**：你有 `[真机]` 和 `[包内]` 两条证据，
但它们支撑的是**另一个更弱的命题**，你却写成了想要的那个强命题。标签齐全 ≠ 结论成立。
判断方法：**把结论和证据并排念一遍，问「有没有第三种解释」**——有就是 `[推断]`。

⭐ **`[包内]` ≠ 功能存在。** 包里有字符串只能证明**这些字节在包里**，⛔ 不能证明
功能上线了、对所有用户可见、或者没被开关关掉。废弃代码、未上线的活、A/B 关掉的分支
都会留下字符串。**凡是「他们有 X 功能」这种话，必须有 `[真机]` 兜底**，只有 `[包内]` 的
一律降级成「包里出现了 X 相关的字符串，未在设备上复现」。

⭐⭐ **技术架构结论几乎永远是 `[推断]`。** 这是本档最容易翻车的地方，因为它看起来最硬：

> ❌ 「识别在云端：`[包内]` 没有端侧推理库 + `[真机]` 飞行模式下功能不可用」

两条证据都真，结论仍然站不住——**本地识别一样可能要联网**（登录校验、按需下载模型、
配额核销）。而且「没有端侧库」只是**没在你拿到的那几个 split 里看到**。正确写法：

> ✅ 「`[真机]` 飞行模式下该功能不可用（录屏 03:22）」
> ✅ 「`[包内]` 已取得的 split 里没有端侧推理库（base + arm64_v8a，feature split 未取）」
> ✅ 「`[推断]` 识别很可能在云端——但本地识别也可能因联网校验而在飞行模式下失败，
>     ⛔ 没有抓包或对方文档之前不能定论」

⛔ 三态里这种结论一律 `PLAUSIBLE`，⛔ 不许因为「两个标签都有」就记 PASS。

### C.1 先问清楚，⛔ 别拿着功能名就去调研

「做自动分章节」这句话里没有需求。至少要问出来：

- **给谁、什么场景用**：会议记录？课堂？采访？三者对分章节的要求完全不同
- **判断做得好的标准**：准确率？速度？可编辑？
- **我方约束**：平台、现有架构、有没有自己的模型、成本上限

⛔ 问不出来就先做「B 模式」找几个参考给用户看，让他在具体东西上表态——
**比逼他凭空回答需求快得多**。

### C.2 真机调研（需要用户授权，且要把代价说清楚）

⚠️ **在竞品 App 上操作不是零成本的**，动手前说明白：

- 会产生**真实数据**（录音、上传、生成内容），可能进对方的服务器
- 可能**消耗额度**——免费次数、试用期，用掉就没了
- 可能要**用户自己的账号**登录；⛔ 不要替用户注册、绑卡、订阅

### ⭐ 先判「够不够得着」，⛔ 别直接开始走清单

2026-09-21 第一次真跑这一档，**第一个目标就卡死在这里**。动手遍历之前先确认两件事：

**① 这个功能你能不能打开？** 常见三种墙：

| 墙 | 表现 | 怎么办 |
|---|---|---|
| **登录墙** | 一进 App 就是 Continue with Google / Email | ⛔ 不注册新号、不绑卡、不动用户账号 ⇒ **换目标**，或请用户决定要不要用自己的账号（⛔ 你不能替他决定） |
| **付费墙** | 功能点进去就弹订阅 | 到弹窗为止的部分照样能量（入口、文案、定价结构），⛔ 别为看全而订阅 |
| **地区 / 设备限制** | 功能不出现 | 记 `SKIP(未覆盖)`，⛔ 不许写成「它没有这个功能」 |

⇒ 够不着的时候，**三种结论要分开标，⛔ 不是一句「全部 PLAUSIBLE」**：

| 你手上的东西 | 标什么 |
|---|---|
| 你**亲眼看到**这里有登录墙 / 付费墙，以及墙前面那些屏 | `[真机]` ⇒ `PASS`。这是实测，⛔ 别因为够不着就自贬 |
| 靠 `[包内]` 字符串推出的「它有 X 功能」 | `PLAUSIBLE` |
| 墙后面没走到的功能与状态 | `SKIP(未覆盖)`，逐条列出 |

⛔ 失败的不是「够不着」，是把够不着的东西写得像验过、或者把已经看到的东西也埋进 SKIP。

**② 它是什么运行时？决定你用什么方式遍历。**

```bash
python3 scripts/feature_probe.py <所有 APK> --section native   # 先看这个
```

⭐ **⛔ 别假设，直接在目标页面试一次 dump**：

```bash
adb shell uiautomator dump /sdcard/ui.xml && adb shell cat /sdcard/ui.xml \
  | tr '>' '\n' | grep -cE 'text="[^"]|content-desc="[^"]'
```

拿到 0 个 ⇒ 退回**截图 + 肉眼读**，点击坐标从截图上量；拿到节点 ⇒ 用 `bounds` 定位，准得多。

| 运行时 | 通常情况 | ⚠️ 但是 |
|---|---|---|
| Flutter / RN | ⚠️ **只有一次观测**：2026-09-21 实测一个 Flutter App **0 个**节点、同时段一个非 Flutter App **16 个**；RN 一个样本都没有 ⇒ ⛔ 别当成频率结论 | ⛔ 但**不是读不到**：Flutter 有 `AccessibilityBridge`（虚拟视图桥接）、RN 把 `accessible` 映射到原生可聚焦节点。⚠️ **那次为什么是 0，我没有定位**——未生成 / 未暴露 / 被合并隐藏 / 采集时机都可能，⛔ 别当成已知原因 |
| 原生 / Compose | dump 通常可用 | ⛔ 也不保证——自绘控件、WebView 内部一样可能是空的 |

⚠️ 系统弹窗（权限、分享）是**另一个进程**，它 dump 得到**不代表** App 界面 dump 得到——
我第一次实跑就是这么误判的。

### 然后才是走清单

⛔ 别随机点。按这张清单**系统地走一遍**，漏掉的状态就是将来返工的地方：

| 要素 | 具体看什么 |
|---|---|
| **入口** | 从哪几个地方能进这个功能？主动触发还是自动发生？ |
| **主路径** | 正常走完一遍，记录每一步的**等待时长**（真实感知的关键） |
| **状态** | 空 / 加载中 / 成功 / **失败** / 权限被拒 / 离线 / 超长输入 —— ⭐ 失败态最能看出功力，也最常被漏 |
| **边界** | 免费能用几次？付费墙卡在哪一步？长度上限？ |
| **联动** | 和其它功能怎么接（分完章节能导出吗？能搜索吗？） |
| **可逆** | 用户能改吗？改完保存在哪？ |

⛔ **顺序很重要：先起日志，再录屏。** 反过来写（先前台录屏、结束后才算日志起点）
**会把录屏期间的日志整段过滤掉** —— 而失败路径恰恰只在那段里。

```bash
# 1) ⭐ 先取起点，⛔ 再打标记 —— 顺序反了标记会被自己的起点过滤掉：
#    标记写在 12:00:00.950、date 返回 12:00:01.000，两条 adb 命令跨个秒就没了。
#    时间取自**设备**，⛔ 不是主机（时区/时钟不一定一致）；`.000` 向下取整到整秒，
#    所以**设备时钟没被回拨**时，之后写的标记不会早于起点。
#    ⚠️ 里层那对引号不能省：`adb shell date '+%m-%d %H:%M:%S'` 会被设备端拆成两个参数，
#    报 `date: Max 1 argument`，`-T` 收到空串后**打个 warning 就退回 -T 1**（2026-09-21 真机实测）
T="$(adb shell "date '+%m-%d %H:%M:%S.000'")"
# 2) 再打标记，后面用它精确切分
adb shell log -t teardown "RUN START"
# 3) 后台起日志
adb logcat -T "$T" > logcat.txt &
LOGPID=$!
# 3) 再录屏
adb shell screenrecord --time-limit 60 /sdcard/feat.mp4
adb pull /sdcard/feat.mp4 . && adb shell rm /sdcard/feat.mp4
# 4) 收工
kill $LOGPID
# 5) 目标页面上单独试一次 dump（见上方，⛔ 别假设读不读得到）
adb shell uiautomator dump /sdcard/ui.xml
```

⛔ **别用 `adb logcat -c`** —— 它清空的是整台设备的日志缓冲，别人正在排查的东西会被你抹掉。
⚠️ `-T 1` 也不是「只从现在开始」——它是「先给最近 1 条已有日志，再继续跟」。
⚠️ 上面 `-T <时间>` 的毫秒固定写 `.000`，所以**边界最多会多读回 1 秒内的旧日志**；
要精确切分就用第 2 步那条 `RUN START` 标记去切。
⛔ **切之前先确认标记真的在采集文件里**（`grep 'RUN START' logcat.txt`）——
设备被校时回拨、或缓冲区被别的进程刷掉，标记都可能不在；缺了就**不能**据此定边界。
⚠️ 这条禁令写进规则之后，**第一次真跑时我自己的脚本里还是用了 `-c`** ——
所以上面直接给的是对的那条命令，⛔ 别自己拼。

⛔ **动手前先把「做到哪为止」说定**，并且**到了就停**：

- 哪个账号（⛔ 不注册新号、不绑卡、不订阅）
- 免费额度**最多用掉几次**——⭐ 触发一次付费墙就够了，⛔ 不要为了「看全」把额度耗光
- 哪些动作**不做**（删除对方数据、修改账号设置、压力测试、连续大量请求）
- 产生的数据事后要不要删

达到范围就停下来汇报，⛔ 不要因为「再点一下就看清楚了」继续。

### C.3 包内取证

```bash
python3 scripts/feature_probe.py base.apk split_config.arm64_v8a.apk \
        --keyword <功能相关词干,多个逗号分隔>
```

⚠️ **把 `pm path` 返回的每一个 APK 都传进去**——原生库在 `split_config.<abi>.apk` 里，
`base.apk` 里一个都没有（实测三个 App）；Android 还有 **feature split**，业务代码可能整块在那里。
第 3 步「拿 base.apk 就够」那条**只对视觉拆解成立**，见 `pitfalls.md` 第 17 条。
⭐ **报告里写清楚你实际分析了哪几个 split，没拿到的标成「未覆盖」**——
⛔ 别让「我没看」看起来像「它没有」。

四类证据各自回答什么：

| 证据 | 回答的问题 |
|---|---|
| **原生库** | 端侧能力的边界。有 `libonnxruntime`/`libtflite` ⇒ **具备**本地跑模型的条件；只有 `libavcodec` ⇒ 具备本地转码条件、**已取得的 split 里没看到端侧推理**。⛔ 两者都推不出「识别一定在云上」，那是 `[推断]` |
| **第三方 SDK** | 他们自己做了什么、买了什么（计费、分析、推送、崩溃） |
| **域名** | 云端依赖和第三方服务 |
| **API 路径** | **功能模块地图** —— 读得出产品有哪几块 |

⛔ **API 路径只用来归纳功能模块，⛔ 不许调用、不许探测、不许把完整清单放进产出物。**
读公开发行包里的字符串是静态分析；拿这些地址去请求对方服务器是另一回事。

⚠️ **Flutter / React Native 的业务逻辑不在 dex 里**（在 `libapp.so` / JS bundle）。
只看 dex 会得出「这个 App 只有 SDK 没有功能」的**系统性错误结论**。
⚠️ 关键词命中**要看来源文件**：ffmpeg 的 `libavcodec.so` 里全是 `speaker`，那是**声道**不是说话人。

（按 C.2 的清单逐项写，每条带标签）

（结合 C.1 问到的我方约束——⛔ 不回答这条，前面写再多也落不了地）

## 三态

- ⭐ **架构类结论（端侧/云端、用了什么方案）默认 PLAUSIBLE**，哪怕两个标签都有——
  ⛔ 标签齐全不等于证据支撑得住这句话
